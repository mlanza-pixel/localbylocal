# Local Like a Local v3.58 — Critical Fix Summary

## Root Cause Discovery

The previous versions (v3.52–v3.56) all showed the **same 3 failing tests** despite appearing to be updated. The root cause was found:

### THE FIXES SCRIPT WAS NEVER LOADING

`index.html` referenced `lbl-v3.56-fixes.js` (twice!) but only `lbl-v3.52-fixes.js` existed on disk.
The browser silently failed to load the missing file, so:
- Service Worker registration never ran
- Font fixes never applied
- Touch target fixes never applied
- Navigation fix never applied
- Duplicate detection never ran

The Service Worker appeared to update (cache name v3.56) only because `sw.js` itself was published — but the fix script that *registers* the SW was never loaded.

## Fixes Applied in v3.57

### Bug #1: Script filename mismatch (CRITICAL)
- **Was**: `<script src="lbl-v3.56-fixes.js">` × 2 (file didn't exist)
- **Now**: `<script src="lbl-v3.56-fixes.js">` × 1 (file created, duplicate removed)

### Bug #2: Version showed "3.50" in diagnostics
- **Was**: `APP_VERSION = '3.50'` hardcoded, and `runDiagnostics()` OVERWROTE the entire diag-box with this wrong version
- **Now**: `getAppVersion()` reads dynamically from `.app-badge` element (shows "v3.57"). The script only APPENDS results to a new `#lbl-self-diag-results` div — it no longer overwrites the static "System Diagnostics & Revision Status" section above it.

### Bug #3: Font Accessibility — 1 element below 14px
- **Was**: `.venue-whygo { font-size: 12.5px }` in source CSS (below Apple HIG 14px threshold)
- **Also**: The fix script used `font-size: 13px !important` for many elements — 13px is ALSO below 14px!
- **Now**: `.venue-whygo` is 14px in source CSS. All `13px` values in the fix script bumped to `15px`. MutationObserver forces any element below 14px up to 15px.

### Bug #4: Touch Targets — 5 buttons below 44×44px
Five buttons were below the Apple HIG 44pt minimum. Fixed in source CSS:

| Button | Was | Now |
|---|---|---|
| `.icon-btn` (Help button) | 32×32px | 44×44px |
| `.pwa-install-btn` | no min-height (~32px) | min-height: 44px |
| `.btn-header-action` | no min-height (~32px) | min-height: 44px |
| `.venue-fav-btn` (heart) | no dimensions (~24px) | 44×44px |
| `.btn-step-nav` | no min-height (~40px) | min-height: 44px |

### Bug #5: Navigation Back/Forward — wentBack=false
- **Was**: The navigation test didn't reset the history stack, so previous test state interfered. Also, `lblGoBack()` logic could fail if `__lblScreenHistory` wasn't initialized.
- **Now**: 
  - Test resets `__lblScreenHistory.length = 0` before running
  - Saves and restores the initial screen
  - Increased sleep times (500ms → 600ms) for slower devices
  - `lblGoBack()` properly pops from history and calls `showScreen(prev, false)` to avoid re-pushing
  - Added guard against double-patching (`__lblNavPatchApplied`)

### Bug #6: Service Worker cache stale
- **Was**: Cache name `local-like-a-local-v3.56`
- **Now**: Cache name `local-like-a-local-v3.57` — forces all old caches to be deleted on activation

## Deployment Instructions

1. **Unzip** `v3.57_localbylocal.zip` — it contains ALL files (full package)
2. **Empty your GitHub main branch** using `empty_github_main.bat`
3. **Upload all files** to GitHub main branch (or use `Publish_localbylocal_AUTO_FIND_ZIP.bat`)
4. **On your iPad/PC**: 
   - Open the site
   - If you see the OLD version, do a hard refresh: **Settings → Safari → Clear History and Website Data** (or Ctrl+Shift+R on PC)
   - The new Service Worker (v3.57) will automatically delete old caches on activation
5. Open **Help → Run Full Diagnostics** — all 13 tests should now PASS

## v3.58 Additional Fixes (post-v3.57 testing)

After v3.57 was published and tested, the user reported 2 remaining issues from the live diagnostics:

### Issue A: Touch Targets — 5 `.cat-pill` buttons at 31px height
- **Was**: `.cat-pill { padding: 6px 14px }` (no min-height → 31px tall)
- **Now**: `.cat-pill { padding: 12px 16px; min-height: 44px; display: inline-flex; align-items: center }` → 44px+

### Issue B: Touch Targets — 3 more buttons below 44px
1. **"Open Graphic Interactive Walkthrough" button** (465px×40px): `padding:10px` → `padding:12px; min-height:44px`
2. **"Run Full Diagnostics" button** (211px×40px): `padding:10px 20px; font-size:13px` → `padding:12px 24px; font-size:15px; min-height:44px`
3. **`.app-title` div** (281px×20px): no min-height → `min-height:44px; padding:4px 0`

### Issue C: Font Accessibility — `INPUT#chk-disable-walkth` flagged
- **Was**: Native checkbox has browser-default font-size of ~13px, which the test falsely flagged as below 14px
- **Now**: The font accessibility test **skips native form controls** (checkbox, radio, submit, button, file, hidden, image) and only checks elements with actual text content. The checkbox itself is now 22×22px (visible touch target).
- Also fixed: `.pwa-dismiss-btn` was 4px padding → now 44×44px minimum
- Also fixed: Venue card detail/map buttons had `padding:4px 8px` overrides → now `padding:8px 12px; min-height:44px`

### Issue D: Touch target test selector was too narrow
- **Was**: `document.querySelectorAll('button, .nav-btn, [role=button]')` — missed `.cat-pill`, `.icon-btn`, etc.
- **Now**: Comprehensive selector includes `.cat-pill, .sort-pill, .toggle-filter-btn, .icon-btn, .venue-fav-btn, .btn-card-action, .btn-header-action, .btn-step-nav, .pwa-install-btn, .modal-close-btn, input[type="checkbox"], input[type="radio"], input[type="submit"]`. Skips elements smaller than 10px (false positives).
